Using ETLLib
************

ETLLib is a command-line toolkit and a Python library (``etl.etllib``) for
munging JSON, TSV, and related data — using Apache Tika_ where field cleanup
helps — and posting the result to Apache Solr_. It is not a workflow engine.
You run the commands from a shell, import the library from Python, or call
them from a Mnemosyne_ pipeline. BigTranslate_ does the last of those.

Typical path::

    tsvtojson → repackage → poster
         TSV        split      Solr

Python 3.10–3.13. Packaging is ``pyproject.toml`` (setuptools). Install with
``pip install -e .`` after libmagic is present (``brew install libmagic`` or
``apt-get install libmagic1``). ``hirlite`` is the optional ``translate``
extra (``pip install -e ".[translate]"``) and often fails to build on current
Python. See the README and the wiki_ for the full install.

Commands
========

Six console scripts install on your ``PATH``. Each is a thin wrapper around
``etl.etllib``. Run ``command -h`` for the live usage string. The installed
similarity command is ``similarity``, not ``imagesimilarity``.

``tsvtojson``
    TSV plus a column-header file → one aggregate JSON file. ``-s`` (Jaccard
    near-duplicate threshold, 0–1) is required; a higher value keeps more.
    ``-j`` refuses to overwrite. Optional columns end in ``:``; a ``*`` suffix
    is also copied to ``id``.

``repackage``
    Pull the list under ``-o`` out of an aggregate JSON and write one
    ``{id}.json`` per record into the current directory. May flatten nested
    structs and Tika-cleanse HTML ``body`` fields.

``poster``
    POST existing JSON documents to Solr's JSON update handler. Paths on stdin
    (one per line) or ``-d`` a directory.

``repackageandpost``
    ``repackage`` then ``poster`` without writing the intermediate files.
    Stdin is a list of *aggregate* JSON paths.

``translatejson``
    Translate named JSON fields via ``tika.translate``, with an rlite cache
    (``-r``). Install the ``translate`` extra for hirlite; it often does not
    build on current Python. For many-to-English at scale, use BigTranslate_
    / Pantogloss instead. There is no Bing cred file.

``similarity``
    Jaccard similarity over Tika metadata (keys or values) for files in a
    directory, then cluster. Writes JSON consumed by the D3 pages under
    ``html/``.

Interactive shells such as csh/tcsh cache ``PATH``; run ``rehash`` after
install if a new command is not found.

Examples
========

Kiva aggregate JSON, one file per team::

    #!/bin/bash
    for ag in /data/xdata/Kiva/raw/RAW__json_teams_9Feb2013/*; do
        repackage -j "$ag" -o teams
    done

Pipe one journal-entries aggregate to Solr without an intermediate file::

    echo "/data/xdata/Kiva/raw/RAW__json_journalEntries_04Mar2013/365/191677_journalentries_pg1_retreived-2013_03_04_21_56.json" \
    | repackageandpost -u "http://localhost:8080/solr/journalentries/update/json?commit=true" -o journal_entries -v

Computrabajo TSV → aggregate JSON → one JSON file per job::

    tsvtojson -t data/staging/computrabajo-ve-20121108.tsv \
              -j data/jobs/tsvtojson/1/output/computrabajo-ve-20121108.json \
              -c conf/colheaders.txt -o employmentjobs -e conf/encoding.txt -s 0.8 -v

    cd data/jobs/repackage/1/output
    repackage -j ../../tsvtojson/1/output/computrabajo-ve-20121108.json -o employmentjobs

Translate selected fields (Tika; needs hirlite). ``-r`` is the SQLite-style
rlite cache path::

    translatejson -i in.json -j out.json -c translate.cols -f es -t en -r ./translation.rdb -v

Similarity over a directory of files::

    similarity -f "$HOME/Pictures" -o ./similarity-out --threshold 0.01 --maxnode 10

Library
=======

The CLIs are the supported interface. The same steps are functions if you
would rather not shell out::

    from etl.etllib import prepareDocs, writeDoc, recoverMisdecoded
    from etl.tsvtojson import detectEncoding, near_dedup_jaccard

These scripts began as DARPA XDATA helpers wrapped by Apache OODT workflows.
Those workflows now run on Mnemosyne_.
